# Support

## Where to get help

| You want to...                                     | Go here                                                                                       |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Read the docs                                      | [kit.arshadshah.com](https://kit.arshadshah.com)                                              |
| Ask a question or share an idea                    | [GitHub Discussions](https://github.com/arshad-shah/kit/discussions)                          |
| Report a bug                                       | [New bug report](https://github.com/arshad-shah/kit/issues/new?template=bug_report.md)        |
| Request a feature                                  | [New feature request](https://github.com/arshad-shah/kit/issues/new?template=feature_request.md) |
| Report a security vulnerability                    | See [SECURITY.md](SECURITY.md) — **do not** open a public issue                                |
| Contribute code                                    | See [CONTRIBUTING.md](CONTRIBUTING.md)                                                        |

## Before opening an issue

1. Check the [docs](https://kit.arshadshah.com) — the question may already be answered.
2. Search [existing issues](https://github.com/arshad-shah/kit/issues?q=is%3Aissue) and [discussions](https://github.com/arshad-shah/kit/discussions) to avoid duplicates.
3. Reproduce against the latest published version of the affected package.

## What makes a useful bug report

- Package and version (`@arshad-shah/<package>@x.y.z`)
- Node version (`node --version`)
- Minimal reproduction — ideally a runnable snippet or a tiny repo. "It doesn't work on my project" is not a repro.
- Expected vs actual behavior
- Stack trace (full, not truncated) and any relevant logs

## What we won't help with via Issues

- General TypeScript or JavaScript questions
- "How do I do X in my app" — use Discussions
- Stack Overflow-style questions

## Response time

This is a single-maintainer project. Reasonable expectations:

- Security reports: acknowledged within 72 hours (see [SECURITY.md](SECURITY.md))
- Bug reports: triaged within ~1 week
- Feature requests: triaged opportunistically; expect a yes/no/maybe with rationale rather than an implementation timeline

If a fix is blocking your work and you'd like to land it yourself, a draft PR with a failing test is the fastest path. See [CONTRIBUTING.md](CONTRIBUTING.md).
